---
title: "扩展概览"
description: "ALP 扩展的声明、协商和兼容原则"
---

扩展用于增加基础协议未规定的可选能力。扩展不能改变核心方法的既有语义，也不能绕过身份、权限、安全、幂等、锁和审计要求。

## 扩展声明

服务端在发现结果的 `capabilities.extensions` 中按稳定标识声明扩展及版本。设备级扩展同时在设备能力清单中声明适用范围。

```json
{
  "capabilities": {
    "extensions": {
      "org.example.capability": {
        "version": "2026-08-31",
        "required": false
      }
    }
  }
}
```

扩展标识必须使用实现方可控制的命名空间。调用方不得在未完成协商时发送扩展字段或调用扩展方法。

## 兼容原则

- 未识别的可选扩展不得影响基础协议使用。
- 扩展新增字段应当是可选字段，并定义缺省行为。
- 改变已有字段含义或删除字段需要新的扩展版本。
- 扩展产生物理副作用时必须显式声明，并遵守基础安全规则。
