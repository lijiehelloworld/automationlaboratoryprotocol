---
title: "提案流程"
description: "通过 GitCode Issue 和合并请求完成提案讨论、验证、评审与发布记录。"
---

1. **提出问题**：搜索 [GitCode Issue](https://gitcode.com/mimedal/all/issues)，已有同类问题时补充场景和证据；没有时，按[提案模板](/docs/proposals/template)新建 Issue。
2. **讨论方案**：在同一条 Issue 中讨论职责边界、接口变化、兼容性和验证方法。作者更新正文，并在评论中说明主要调整，保留设计变化的记录。
3. **提交修改**：方案明确后提交[合并请求](https://gitcode.com/mimedal/all/pulls)，与提案 Issue 相互链接，同时更新受影响的规范、示例和测试。
4. **验证与评审**：按[贡献指南](/docs/community/contributing)提供检查结果。区分文档检查、模拟测试和实际设备测试，未执行的检查不能写成已通过。
5. **记录决定**：维护者在 Issue 或关联的合并请求中记录接受、拒绝、暂缓或撤回的结论及理由，不以关闭 Issue 代替决定说明。
6. **关联发布**：合并后记录合并请求和提交；发布完成后补充发布版本或对应提交、正式页面链接，便于追溯改动和生效范围。

引用提案时使用 Issue 链接及 GitCode 分配的编号，不再另设一套编号。状态改变应保留历史记录和决定理由。

接受提案、合并修改和完成发布是不同状态。讨论中的建议和已合并但未发布的修改，不自动成为已发布规范的要求。

平台操作参考：[创建 Issue](https://docs.gitcode.com/docs/help/home/org_project/issue/create_issue/)、[创建合并请求](https://docs.gitcode.com/docs/help/home/org_project/pullrequests/pr-create/)。
