ALL 语言引擎从 FSP 层读取设备能力、使用边界和约束，通过智能体（Agent）根据实验目的生成任务流程。编译/解释器整理流程，仿真器计算和校验并反馈问题；执行器解析通过仿真的任务，确认当前可用设备后下发给 FSP。FSP 服务通过动作契约、能力门控和转发器连接设备仪器接口。

## 总体架构

```mermaid
flowchart TB
    G[实验目的、成功条件与对象初态]
    subgraph L[ALL 语言引擎]
        R[读取设备能力、使用边界与约束]
        A[通过 Agent 生成实验任务流程]
        C[编译/解释器：整理步骤与依赖]
        S[仿真器：计算与校验]
        E[执行器：解析任务、确认设备可用、下发]
        R --> A --> C --> S
        S -->|问题反馈与修订| A
        S -->|通过并保存验证记录| E
    end
    G --> A
    F[FSP 服务：动作契约、能力门控、转发器]
    F -->|能力、边界与约束| R
    E -->|下发前查询最新状态| F
    F -->|状态、任务进度与实际结果| E
    E -->|条件满足后提交任务| F
    E -->|需要重新规划：保留已执行结果| A
    subgraph D[设备仪器接口]
        I[必须提供操作、对象、系统三方面信息]
        H[接口实现、驱动、硬件服务与物理设备]
    end
    F -->|设备命令| I
    I -->|实际状态与结果| F
```

## 数据流

```text
FSP 提供设备能力、使用边界、约束
  → 语言引擎读取能力
  → Agent 根据实验目的生成任务流程
  → 编译/解释器整理流程
  → 仿真器计算与校验
      未通过：把问题反馈给 Agent，修订后重新编译和仿真
      通过：交给执行器解析任务
  → 执行器向 FSP 查询最新状态，确认可用设备和对象条件
      不可用：等待后重新查询，或返回语言引擎修订并重新仿真
      可用：向 FSP 下发任务
  → FSP：动作契约检查 → 能力门控 → 转发器 → 设备仪器接口
  → 实际结果、对象变化和任务状态返回执行器
```

设备可以保留既有接口。FSP 要求设备仪器接口从操作、对象、系统三个维度提供完整内容：既要说明动作和实际结果，也要说明相关对象的状态变化以及设备、安全、任务和资源状态。三者不是三套独立接口。

规划使用的能力说明和下发前读取的当前状态分别承担不同职责。执行器确认可用之后，FSP 仍须在放行动作前核对实时条件并取得所需资源。完整流程和反馈规则见[协议概述](/docs/specification/overview)。
