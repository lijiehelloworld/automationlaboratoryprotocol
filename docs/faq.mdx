## ALL 和 FSP 是什么关系？

ALL 是完整语言，包含编译/解释器、仿真器和执行器。FSP 是 ALL 内部面向设备的函数状态协议；其服务实现由动作契约、能力门控和适配器组成。

## 设备必须原生实现 FSP 吗？

不需要。现有 HTTP API、CLI、MCP 工具、厂商 SDK、RPC、消息接口或驱动都可由适配层映射为 FSP。

## 为什么厂商接口要包含操作、对象和系统？

这是 FSP 对厂商设备接口提出的三方面内容要求：操作说明做什么、参数和结果；对象说明操作哪个容器或样品及其状态变化；系统说明设备状态、安全限制、任务和资源。三者不是三个独立服务，也不要求厂商建立三套接口，但厂商接口提供的调用、查询、回调或事件必须能够完整给出这三方面信息。

## 异步任务属于哪个模块？

异步任务属于 FSP 系统部分。操作受理后可返回任务标识；后续状态、结果和取消信息通过系统任务返回。

## 仿真通过是否等于实验成功？

不等于。仿真只说明步骤通过了已定义的检查，不证明真实设备或样品会达到预期。执行时仍要检查容器和设备状态，并按实际测量和检查结果判断是否成功。
