判断一个实现是否符合 FSP，要看它是否满足正文中的强制要求。使用 HTTP、CLI、MCP、RPC 还是 SDK 不是判断依据；关键是对象、操作、系统三部分是否完整，实际处理是否符合规定。

## 接口必须做到什么

设备接口或适配层必须满足以下要求：

1. 对每项操作提供对象、操作和系统三个部分的说明；
2. 在输入中表达目标容器与执行前状态、操作参数与约束、设备条件与安全限制；
3. 在输出中表达实际对象状态变化、操作执行结果与诊断、系统状态与安全事实；
4. 校验参数类型、范围、枚举、对象状态、系统版本号和执行前条件；
5. 对异步操作在系统段返回任务状态，并提供结果读取能力；声明取消支持范围，不支持或不安全时明确拒绝取消；
6. 在失败、取消或结果未知时保留当前已经确认的信息，不得提交预期成功状态。

## 基础检查

| 编号 | 验证内容 | 通过条件 |
| --- | --- | --- |
| C01 | 接口说明 | 每项操作均有对象、操作、系统三段定义 |
| C02 | 输入校验 | 缺少任一维度或参数不符合类型、范围、枚举时拒绝执行 |
| C03 | 对象校验 | 目标容器存在、类型兼容、状态和容量满足条件 |
| C04 | 系统校验 | 设备状态、版本号和安全限制在动作前通过 |
| C05 | 结果结构 | 响应同时包含对象变化、操作结果、系统状态与注意事项 |
| C06 | 异步语义 | 每次任务结果均返回对象、操作、系统三部分结果，取消不提交预期成功状态 |
| C07 | 失败语义 | 失败诊断可定位到对象、操作或系统条件 |

## 运行时需要测试的情况

下面列出实现必须测试的情况，不表示本仓库已经做过这些设备测试。每项要记录请求、执行前状态、实际发送命令的次数、返回结果、保存的状态和证据。使用模拟驱动的测试与真机测试要分开记录。

| 编号 | 场景与关联条款 | 必须观察到的结果 |
| --- | --- | --- |
| C08 | 契约已注册但无当前设备绑定（CAP01–02、ADP01） | 拒绝；下发次数为 0；不选择其他设备同名实现 |
| C09 | 能力已实现但缺少配置，或资源被占用（CAP03、SYS01） | 分别返回未就绪或资源冲突；不能由静态 Skill 绕过 |
| C10 | 目标版本正确但来源容器版本过期（OBJ01、SYS02） | 整个操作拒绝，下发为 0；源和目标都参与检查 |
| C11 | 两个请求争用同一容器（LIF02） | 最多一个任务进入动作阶段，另一个不越过互斥边界 |
| C12 | 受理响应丢失后以原键重试（LIF03） | 返回原任务；底层动作不重复；旧预期版本不造成新任务 |
| C13 | 同键修改体积或目标（LIF03） | 幂等冲突，下发次数不增加 |
| C14 | 设备只有 ACK，无契约要求的完成证据（OPS01–03） | 不标为 succeeded；保留任务、缺失证据和恢复路径 |
| C15 | 已部分加液后通信中断（OBJ02、LIF01–02） | 记录已确认变化，未确认体积失效；unknown 保持必要占用 |
| C16 | 取消与完成并发（LIF04） | 取消请求不直接生成 cancelled；按证据确认最终状态，不覆盖已完成事实 |
| C17 | 提交过期、错容器、未授权或模拟观测（LIF05） | 拒绝作为真实完成依据；原任务与保护状态不被绕过 |
| C18 | 持久化受理后崩溃、下发后崩溃、结果落盘前崩溃（LIF06） | 原键与任务可恢复；无法证明未下发时不自动补发；进入核实流程 |
| C19 | 查询缓存或反复轮询（SYS02、LIF06） | 不伪造新观测时间，不随意改变状态版本号 |
| C20 | 下发前现场状态改变（LIF02、安全要求） | 锁内复核失败时不动作；任务返回明确诊断 |
| C21 | MCP、HTTP、CLI 等绑定转换（CON01、ADP03） | 等价输入产生相同语义；多处设备标识或幂等键冲突时拒绝 |
| C22 | 最终状态后到达迟延或冲突证据（LIF01、LIF05） | 不覆盖最终状态历史；追加可审计纠正记录，必要时阻止依赖动作 |

不支持的可选能力可以声明不适用，并验证拒绝路径；不能把强制安全、幂等或实际结果要求标为不适用。通过 C01–C07 的结构检查不等于通过 C08–C22 的行为验证。

## 声明示例

```json
{
  "implementation": "example-device-adapter",
  "fsp_version": "0.1",
  "interface_contract": {
    "dimensions": ["object", "operation", "system"],
    "transport_agnostic": true,
    "asynchronous_result_supported": true
  }
}
```

此声明不要求公开接口 URL、命令名或供应商实现细节。

上面的 `fsp_version` 仅为声明格式示例，不构成本次规范发布或版本升级。正式声明必须指定所依据文档的版本或提交、操作契约版本、设备定义版本、支持的操作和调用方式，并附 C01–C22 逐项结果及未验证项。不得仅凭此 JSON、工具可发现或代码静态检查宣称完整符合性。
