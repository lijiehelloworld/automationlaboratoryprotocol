Function State Protocol（FSP，函数状态协议）用于把上层的函数调用变成可检查、可执行、可核对结果的设备动作。

FSP 服务的具体实现由三部分组成：

1. **动作契约**：定义动作的含义、参数、前置条件、结果和完成证据；
2. **能力门控**：确认目标设备硬件支持、代码已实现、配置已就绪，且当前条件允许执行；
3. **适配器**：把通用动作转成具体设备命令，再把驱动返回值转成通用结果。

底层设备接口则必须从 **操作、对象、系统** 三个维度表达一次调用。这三个维度不是 FSP 服务的三个执行模块，而是适配器调用底层接口时必须传递和返回的信息。

## FSP 服务的执行顺序

```text
上层函数调用
  → 动作契约：解析动作和校验参数
  → 能力门控：选定设备并检查是否允许执行
  → 适配器：转换单位、坐标和命令，调用驱动
  → 设备接口：返回操作、对象、系统三个维度的实际信息
  → FSP 服务：按契约判断成功、失败或结果未知
```

动作契约通过不代表可以下发；能力门控通过也不代表设备已经完成动作。只有取得契约要求的实际结果和完成证据，才能返回成功。

## 设备接口的三个维度

| 维度 | 请求要表达 | 返回要表达 |
| --- | --- | --- |
| [操作](/docs/specification/device-integration/operations) | 动作标识、参数、版本和执行前条件 | 是否执行、实际参数、结果、诊断和完成证据 |
| [对象](/docs/specification/device-integration/objects) | 相关容器、样品、角色、位置和执行前状态 | 实际变化、当前状态、观测时间和对象版本 |
| [系统](/docs/specification/device-integration/system) | 设备状态、安全限制、资源、幂等键和执行模式 | 实际设备状态、安全检查、任务、资源占用和注意事项 |

一次设备调用必须同时表达这三个维度，但可以使用 HTTP、CLI、MCP、RPC 或厂商 SDK 作为承载方式。FSP 不规定 URL、工具名、命令名或 SDK 方法名。
