仿真器接收编译/解释器整理后的实验任务流程，以及语言引擎从 FSP 获取的能力、使用边界、约束和对象初态。它在独立状态副本中逐步计算预测变化并校验条件，把计算结果和问题反馈给 Agent，供下一轮修订使用。

## 计算、校验与循环反馈

计算用于回答“执行这一步后预计发生什么”，例如声明了体积可加和模型时的来源余量、目标体积，以及设备状态的预计变化。校验用于回答“这一步是否满足能力范围、对象条件、顺序依赖和安全约束”。每个计算结果都要说明使用的模型、输入和假设。

一次仿真返回预测状态、已检查条件、出错步骤、违反的约束和待现场确认项。Agent 根据这些信息修订候选流程，再由编译/解释器检查，并重新仿真。循环在必检项通过时结束；达到修订上限、缺少必要信息或现有能力无法满足实验目的时，返回明确原因。

通过记录必须关联具体流程、参数、能力版本和初始状态。修订后使用新记录；不能沿用旧流程的通过结论。待现场确认项随流程交给执行器，在下发前由 FSP 的实时信息和有来源的现场记录核对。

## 先检查，再更新

动作先收集全部适用条件，再决定是否提交状态效果。必检条件失败时，受影响的预测状态保持不变；诊断日志可以追加。建议条件形成警告，并保留处理结论。

![仿真校验与预测状态更新](/images/all-simulator-flow-gptimage.png)

加液仿真逻辑如下，采用无损转移、体积可加和的模型：

```text
读取来源和目标容器的预测状态
检查两个容器已登记且不同，体积与容量数据有效
检查加液量为有限正数，单位和范围符合动作契约
检查来源余量、目标剩余容量及容器条件
若任一检查失败：保留原状态，返回原因
否则：
  来源预测体积 = 原体积 - 加液量
  目标预测体积 = 原体积 + 加液量
  返回新的预测状态和检查记录
```

实际动作还要检查容器类型、开闭状态、位置和设备专属条件。缺失规则必须列出。

## 检查与诊断策略

| 检查 | 典型问题 | 处理 |
| --- | --- | --- |
| 参数 | 单位不符、非有限数、越界 | 定位参数并拒绝状态更新 |
| 对象 | 未登记、余量不足、状态不匹配 | 指明对象及前置条件 |
| 顺序 | 前一步没有产生所需状态 | 返回依赖位置 |
| 控制流 | 未知条件、循环未收敛、分支写冲突 | 按控制节点报告 |
| 设备局部状态 | 已知开盖时启动离心 | 拒绝动作 |
| 现场信息 | 配平、装载、锁状态缺少证据 | 列为运行时待验证项 |

遇错继续模式便于收集诊断，但失败动作的效果不能提交。后续依赖失败结果的步骤应标为阻塞或带上依赖诊断，不能沿用虚构的成功状态。

```json
{
  "simulated": true,
  "status": "failed",
  "step_id": "transfer-2",
  "object_id": "target-01",
  "code": "capacity_exceeded",
  "severity": "error",
  "expected": "最终体积不超过 2 mL",
  "observed": "预测最终体积为 3 mL",
  "remediation": "核对容器或修改经确认的加液方案"
}
```

Agent 按诊断修订相关步骤，保留实验目的、成功条件与修改记录，再经过编译/解释检查和仿真。不得删除失败规则来获得通过结果。更换容器、改变剂量或删除步骤时，还要重新核对科学目标。

## 仿真结果

仿真结果应列出使用的模型及适用范围、已检查条件、预测状态、错误、警告和待现场验证项。缺少模型或输入数据的项目应标为未验证；必检项目未验证时，不得判定仿真通过。

设备当前状态、对象实际位置、装载和配平等现场条件，由执行器在下发前确认。仿真记录关联具体流程、参数、初始状态和契约版本；这些信息变化后，应重新验证受影响的步骤。

## 计算与校验示例

### 加液量与容量检查

来源初始体积为 10 mL，目标容器初始为空，计划加液 0.5 mL。按无损转移、体积可加和模型计算：

| 条件 | 计算与处理结果 |
| --- | --- |
| 目标容量为 2 mL | 来源预测体积为 9.5 mL，目标预测体积为 0.5 mL |
| 目标容量为 0.3 mL | 返回容量不足；本步骤不更新状态 |
| 来源余量不足或体积未知 | 返回诊断；不继续依赖该步骤的操作 |
| 对象不在指定设备 | 返回位置不符；要求先确认转移 |

### 离心步骤检查

```text
设置转速与时长 → 关盖 → 启动

检查转速与时长是否在设备公布范围内
检查启动前已有程序配置，且盖子已关闭
已知未装载或未配平：返回错误
装载或配平情况未知：列为待现场确认项
执行器下发前取得并核对现场证据
```

### 状态保留与反馈

每一步先在独立状态中检查和计算，全部通过后再更新预测状态。失败时保留此前已通过步骤的结果，停止后续依赖步骤，并返回步骤编号和原因。流程修订后重新仿真，生成新的验证记录。
