ALL 把实验目的变成设备可以执行的实验任务流程。语言引擎先从 FSP 层获取设备能力、使用边界和约束，再通过智能体（Agent）生成候选流程；编译/解释器整理流程，仿真器做计算和校验，将问题反馈给 Agent 修订。流程通过仿真后，执行器解析任务，在下发前重新向 FSP 查询设备和对象的当前状态，确认设备可用，再交给 FSP 执行。

| 模块 | 职责 |
| --- | --- |
| Agent | 根据实验目的、成功条件和 FSP 提供的能力与约束生成流程，并根据仿真诊断修订流程 |
| 编译/解释器 | 整理能力说明和候选流程，检查调用、参数及依赖，解释顺序、分支和循环 |
| 仿真器 | 根据已声明的模型计算预测变化，检查步骤、对象和设备约束，返回诊断与待现场确认项 |
| 执行器 | 解析已通过仿真的流程，查询当前可用设备和对象状态，核对条件后向 FSP 下发任务并跟踪结果 |
| FSP | 向语言引擎提供能力、边界、约束和状态查询；通过动作契约、能力门控和转发器执行设备动作并返回真实结果 |

## FSP 提供什么，语言引擎使用什么

| 信息 | 具体内容 | 使用时机 |
| --- | --- | --- |
| 设备能力 | 已实现的动作、参数和单位、返回结果、完成条件及版本 | Agent 选择可用动作，编译/解释器绑定具体定义 |
| 使用边界 | 参数范围、适用样品和容器、工作范围、标定条件、模型覆盖范围及未知项 | 生成流程和仿真时限制可选方案 |
| 约束 | 操作前提、先后依赖、权限、安全条件、资源互斥及部署限制 | 编译、仿真和真实执行前分别检查 |
| 当前状态 | 在线或故障状态、忙闲与资源占用、对象位置及状态、观测时间与版本 | 执行器下发前确认设备可用，FSP 放行动作前再次核对 |

能力说明回答“设备能做什么”；当前状态回答“这次能否执行”。规划时读取过能力，不能省略下发前的状态查询。FSP 提供的数据缺少必要范围、约束或状态时，语言引擎必须报告缺失。

## 两个反馈过程

**生成与仿真反馈**：仿真器把出错步骤、计算结果、违反的约束和缺失信息交回语言引擎。Agent 保持实验目的和成功条件，修订流程后重新编译和仿真。修订次数必须有上限；信息不足或无法通过时，返回原因和待补充内容。

**执行反馈**：执行器在每段任务下发前查询 FSP。设备忙碌时按规则等待并重新查询；设备、参数、对象状态或能力约束改变并影响已验证流程时，返回语言引擎重新规划和仿真。已经执行的步骤及其实际结果必须保留，不能从头重复实验。FSP 收到任务后仍要在取得资源、准备执行动作时重新检查条件。

设备可以保留原有 API、SDK 或驱动，由 FSP 转发器完成命令和结果映射。设备仪器接口要提供操作、对象、系统三个方面的信息。仿真记录说明模型内的计算与检查结果；实验是否完成，由 FSP 返回的实际结果和完成证据判断。
