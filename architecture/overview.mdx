Automation Laboratory Language（ALL）覆盖从科学目标到设备执行和证据反馈的完整闭环。FSP 位于 ALL 内部，负责设备发现、技能披露、分类请求和状态结果通信。架构图说明协议关系，不规定服务端内部部署方式。

<Note>每项设备技能都从对象、控制和系统三个维度说明；三个维度不是三类独立能力。</Note>

## 模块关系

1. FSP 发现设备，先返回技能摘要，再按需披露所选技能的对象、控制和系统三个完整维度。
2. 设备技能描述经过质量评估，通过后进入合格设备技能库。
3. 实验编排代理结合科学目标、研究对象状态和合格设备能力生成函数式实验方法。
4. 候选方法经过可计算性、状态闭合、物理约束仿真和科学语义评审。
5. 验证后的方法绑定具体设备，转换为可下游执行的步骤和路径。
6. FSP 按 `read`、`write`、`invoke` 分类约束下发请求，验证后的结果更新研究对象状态并形成证据和诊断反馈。

## 最小交互逻辑

```text
FSP 设备发现
  → 技能摘要与按需详情
  → 技能说明与质量准入
  → 研究对象状态上下文
  → 函数式实验方法生成与验证
  → 设备绑定与 FSP 执行
  → 状态提交与证据反馈
```

## 模块输入输出

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| FSP | 设备接口与当前状态 | 渐进披露的技能定义、状态和执行结果 |
| 技能提取 | FSP 完整技能定义 | 通过评估的设备技能描述与函数式技能 |
| 对象 | 科学身份、样品、容器和状态 | 方法生成上下文 |
| 函数式实验方法 | 科学目标、上下文和合格能力 | 代码式方案和转换 JSON |
| 方法验证 | 代码式方案与同版本函数库 | 仿真报告、阻断诊断或通过结果 |
| 设备绑定与执行 | 验证后的方案 | 设备步骤、路径、结果和状态变化 |
