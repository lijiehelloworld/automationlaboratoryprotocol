身份认证和 OAuth 授权见[身份认证与授权](./authentication)。本章规定通过授权后仍必须执行的设备安全要求。

## 分层安全

| 层级 | 责任 |
| --- | --- |
| 授权服务器 | 主体认证、授权同意和令牌签发 |
| ALL 服务端 | 令牌校验、方法与资源授权、数据结构、修订号、前置条件、约束、执行锁和审计 |
| 设备本地安全层 | 急停、限位、安全门、硬实时联锁和物理参数上限 |

任何上层授权都不得关闭或绕过设备本地安全层。

## 执行前安全顺序

改变物理状态前，服务端必须完成：

1. 验证令牌、发行方、受众、有效期和权限；
2. 确认设备、对象、操作和 Workflow 对当前身份可见；
3. 校验请求数据结构和单位；
4. 校验设备与对象修订号；
5. 校验状态新鲜度；
6. 校验对象角色、位置和关系；
7. 校验前置条件和物理约束；
8. 校验截止时间、超时和人工批准；
9. 获取设备与参与对象执行锁；
10. 在锁内重新检查易变条件；
11. 才能向底层设备发送命令。

任一步失败都不得接触物理设备。

## 执行锁

- 所有真实硬件入口必须共享同一设备执行锁体系。
- 操作涉及作业对象时必须同时锁定对象，且锁顺序必须确定，避免死锁。
- Workflow 在步骤之间可以保持设备所有权，但不得无限持锁。
- 读取可以并发，前提是设备声明读取不会干扰正在执行的操作。
- 管理页面、维护接口和内部任务不得绕过同一锁。

## 结果确认

服务端必须区分：

```text
请求已接收
命令已发送
设备报告完成
物理结果已确认
物理结果未知
```

只有操作定义要求的确认条件全部满足时才能返回 `outcome=succeeded`。底层仅报告“命令已发送”时不得视为完成。

设备断连、超时、部分执行或确认来源冲突时必须返回 `outcome=unknown`，并阻止依赖未知结果的后续物理步骤。

## 试运行

`dry_run=true` 必须执行数据结构、权限、对象、修订号、前置条件和约束校验，但不得：

- 发送设备命令；
- 修改系统或对象状态；
- 消耗物理对象；
- 长时间占用执行锁；
- 生成表示真实执行成功的证据。

试运行通过不保证正式执行时状态仍然有效。

## 取消

取消是协作式安全请求，不是强制终止进程：

- 服务端必须检查当前阶段是否可取消；
- 设备必须执行声明的安全收尾；
- 只有达到确认安全终态后才能返回 `cancelled`；
- 无法确认时返回 `unknown`；
- 急停属于设备本地安全机制，不等同于普通取消接口。

## 最小暴露

标准能力不得公开：

- 任意串口帧；
- 任意寄存器读写；
- 固件调试入口；
- 通用脚本执行；
- 维修强制动作；
- 绕过限制的原始 SDK 调用；
- 访问令牌、密钥或内部网络端点。

## 审计

改变状态的请求至少记录：

```text
request_id
trace_id
issuer
verified_subject
client_id
granted_scopes
device_id
method
operation_or_workflow
object_ids
validated_arguments_digest
previous_revisions
new_revisions
authorization_decision
started_at
completed_at
outcome
error
evidence_ids
```

审计记录必须防篡改、按部署策略保留并限制访问。不得记录访问令牌、授权码、客户端密钥、无必要的对象敏感属性或底层调试秘密。

## 输出安全

设备说明、对象属性、操作结果和 Workflow 文本都属于不可信数据。客户端不得把这些内容解释为新的权限、系统提示或绕过安全规则的指令。

服务端必须限制返回大小、文本长度、嵌套深度和下载地址有效期。操作返回的下载地址必须经过当前身份授权，并绑定明确内容类型与摘要。
