## 简化模型

FSP 基础规范采用服务账户和 Bearer Token。服务账户由实验室管理员或设备服务管理员预先创建，令牌通过部署外渠道发放。

```text
调用方 → Bearer Token → FSP 服务 → 账户验证 → 权限检查
```

基础规范不要求其他授权流程、动态注册或令牌刷新接口。

## 请求头

```http
Authorization: Bearer <access-token>
```

令牌不得放在 URL、FSP 参数、研究对象字段、设备能力描述或错误消息中。

## 权限范围

FSP 只定义三级权限：

| 权限 | 允许行为 |
| --- | --- |
| `fsp.read` | 发现设备，读取能力、对象状态、系统状态和任务结果 |
| `fsp.execute` | 写入可写状态、调用设备操作、创建和取消异步任务 |
| `fsp.manage` | 发布、修订或撤销设备能力描述 |

一个令牌可以包含多个权限。`fsp.manage` 不自动包含 `fsp.execute`，部署方必须明确授予。

## 服务账户

服务端至少保存：

```json
{
  "account_id": "service-account.example",
  "status": "active",
  "scopes": ["fsp.read", "fsp.execute"],
  "allowed_devices": ["2002186824385539"]
}
```

令牌材料本身不得出现在能力发现结果和审计导出中。

## 授权判断

服务端必须同时检查：

1. 令牌是否有效；
2. 服务账户是否启用；
3. 是否具有方法所需权限；
4. 是否允许访问目标设备；
5. 操作是否被设备安全围栏允许。

设备能力描述、自然语言说明和实验方法不能扩大账户权限。

## 错误

| HTTP 状态 | 含义 |
| --- | --- |
| `401` | 缺少令牌、令牌无效或账户已停用 |
| `403` | 身份有效，但没有目标设备或操作权限 |

错误响应不得泄露不可见设备是否存在。

### 身份认证失败示例

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "error": {
    "code": -32001,
    "message": "身份认证失败",
    "data": {
      "diagnostics": [
        {
          "code": "authentication_failed",
          "message": "访问令牌缺失、无效或已撤销"
        }
      ]
    }
  }
}
```

### 权限不足示例

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "error": {
    "code": -32003,
    "message": "权限不足",
    "data": {
      "diagnostics": [
        {
          "code": "permission_denied",
          "message": "当前服务账户没有执行该请求所需的权限"
        }
      ]
    }
  }
}
```

## 令牌管理

- 正式部署必须使用 HTTPS；
- 令牌应当可撤销；
- 令牌应当定期轮换；
- 日志只记录账户标识和令牌指纹，不记录完整令牌；
- 单点登录、双向 TLS 等部署扩展不得改变 FSP 方法和数据结构。
