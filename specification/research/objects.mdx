## 研究对象

研究对象（Research Object）是实验过程中被处理、观察或表征的科学对象。规范结构包括：

```text
identity
sample
container
state
location
evidence
provenance
extensions
```

FSP 只负责设备可见的容器和状态；ALL 方法层把这些状态与科学身份、证据和来源组合成研究对象上下文。

## 顶层 Schema

| 字段 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `identity` | `object` | 是 | 研究对象稳定标识、类型和名称 |
| `sample` | `object` | 是 | 样品状态和可量化信息 |
| `container` | `object` | 是 | 当前承载容器及其静态、动态属性 |
| `state` | `object` | 是 | 当前修订号和设备可确认状态 |
| `location` | `object` 或 `null` | 是 | 当前所在设备或外部位置；未知时为 `null` |
| `evidence` | `array[object]` | 是 | 支持当前状态的仿真、观测、测量或执行结果引用 |
| `provenance` | `array[object]` | 是 | 对象创建、状态提交和更正记录 |
| `extensions` | `object` | 是 | 命名空间隔离的扩展字段 |

## 分区字段

### 身份 `identity`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `object_id` | `string` | 研究对象稳定标识 |
| `object_type` | `string` | 研究对象类型 |
| `name` | `string` 或 `null` | 面向人的名称 |

### 样品 `sample`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sample_status` | `string` | 沿用能力声明的样品状态 |
| `sample_volume` | `number` 或 `null` | 样品体积；未知时为 `null` |
| `volume_unit` | `string` 或 `null` | 与体积分离表达的单位 |
| `source_bottle_ids` | `array[int]` | 现有加液返回中的原液瓶编号列表 |

### 容器 `container`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `container_id` | `integer` 或 `string` | 设备能力使用的容器编号或稳定标识 |
| `container_type` | `string` | 容器类型 |
| `container_status` | `string` | 有盖、无盖等设备可确认状态 |
| `shape` | `string` 或 `null` | 形状 |
| `diameter_mm` | `number` 或 `null` | 适用时的直径 |
| `height_mm` | `number` 或 `null` | 适用时的高度 |
| `material` | `string` 或 `null` | 材质 |

### 状态、位置、证据与来源

| 分区 | 必需内容 |
| --- | --- |
| `state` | `revision`、设备返回的当前状态字段、观测时间 |
| `location` | 当前设备标识；没有可信位置时使用 `null` |
| `evidence[]` | 证据类型、结果引用、产生时间；不能嵌入访问凭据 |
| `provenance[]` | 变更类型、相关操作或方法引用、时间和提交主体 |
| `extensions` | 以实现者控制的命名空间组织，不能覆盖标准字段 |

`skill_all` 当前没有完整研究对象、证据和来源产物，因此本页不构造伪造的完整实例；下面只使用已有能力和执行计划中实际出现的容器与样品字段说明状态演化。

## 现有输入字段

`skill_all` 的工作站能力和方案使用以下实际字段：

```text
container_type
container_count
container_ids
container_status
sample_status
sample_volume
source_bottle_ids
```

方法生成和验证示例必须沿用这些字段，不替换成没有实现依据的新标识体系。

## 初始状态示例

来自现有开盖能力：

```yaml
container_type: 进样瓶
container_count: 2
container_ids: [1, 2]
container_status: 有盖
sample_status: 空
```

## 状态变化示例

```text
开盖：
  container_status: 有盖 → 无盖

加液：
  container_status: 无盖 → 无盖
  sample_status: 空 → 液体

关盖：
  container_status: 无盖 → 有盖
  sample_status: 液体 → 液体
```

## 操作输出示例

现有加液操作返回容器列表：

```json
{
  "containers": [
    {
      "container_type": "进样瓶",
      "container_status": "无盖",
      "sample_status": "液体",
      "container_id": 1,
      "sample_volume": 0.5,
      "source_bottle_ids": [1]
    }
  ]
}
```

## 容器静态属性

容器类型还应包含用于兼容判断的静态属性：

```json
{
  "container_type": "进样瓶",
  "shape": null,
  "diameter_mm": null,
  "height_mm": null,
  "material": null
}
```

`skill_all` 没有提供这些静态值，因此示例只保留字段。静态属性来自设备提供的数据或经过确认的容器目录，不得由方法生成器猜测。

## 状态上下文输出

方法生成器获得的上下文至少包含：

```text
科学目标
研究对象身份
容器类型和编号
当前容器状态
当前样品状态
已有样品体积
可用设备能力
强制约束
已有证据和来源
```

## 状态提交

- 只有操作完成并满足完成条件后才能提交新状态；
- 仿真失败、版本不兼容或强制约束失败时不提交状态；
- 设备结果未知时重新读取状态，不假定成功；
- 每次状态提交都应当关联产生它的操作、参数和证据。
