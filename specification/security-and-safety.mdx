## 分层安全

ALL 的安全控制分为四层：

1. Bearer Token 验证服务账户；
2. 权限范围限制读取、执行和管理行为；
3. FSP 根据参数、对象状态、前置条件和系统安全围栏校验操作；
4. 设备本地控制器保留最终硬件保护权。

上层实验方法、能力描述或自然语言内容不得绕过任何一层。

## 执行前校验顺序

改变设备状态的请求应当依次检查：

```text
身份 → 权限 → 设备可见性 → 能力修订号 → 参数 Schema
→ 对象与系统状态新鲜度 → 前置条件 → 操作约束 → 安全围栏 → 资源锁
```

任一检查失败，服务端不得下发设备动作。

## 状态与并发

- 改变状态的调用必须携带 `expected_revision`；
- 同一对象或同一互斥设备资源的冲突操作不得并发执行；
- 只有设备确认完成后才能提交成功状态；
- 任务进入 `unknown` 后不得以计划状态覆盖实际状态；
- 并行函数必须声明汇合条件和写集合，冲突写入必须在执行前被拒绝。

## 安全围栏

系统能力必须公开调用方需要知道的安全限制，例如允许运行状态、联锁条件、可用性、禁止条件和紧急停止状态。围栏只公开执行判断所需信息，不暴露内部控制秘密。

## 取消与急停

取消任务是请求，不等同于动作已经停止。服务端必须返回真实任务状态；不能安全取消时返回 `unsafe_cancellation`。紧急停止由设备本地安全机制实施，ALL 只能读取其状态并遵守其结果。

## 最小暴露

- 能力发现只返回账户可见设备；
- 日志不记录完整令牌、设备密码或未脱敏样品秘密；
- 诊断不返回内部堆栈和驱动密钥；
- 研究对象扩展字段不得用于携带访问凭据。

## 审计

改变状态的调用至少记录账户、设备、操作、请求标识、时间、参数摘要、输入修订号、任务标识、最终状态和诊断编码。审计记录不能代替研究对象的实验来源与证据。
