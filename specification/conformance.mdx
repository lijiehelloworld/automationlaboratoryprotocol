符合性以规范正文中的强制条款为准。FSP 符合性不取决于 HTTP、CLI、MCP、RPC 或 SDK 等承载方式，而取决于接口是否完整实现对象、控制和系统三段契约。

## FSP 接口符合性

一个符合 FSP 的设备接口或适配层必须：

1. 对每项操作提供对象、控制和系统三个维度的说明；
2. 在输入中表达目标容器与执行前状态、控制参数与约束、设备条件与安全围栏；
3. 在输出中表达实际对象状态变化、控制执行结果与诊断、系统状态与安全事实；
4. 校验参数类型、范围、枚举、对象状态、系统修订号和前置条件；
5. 对异步操作在系统段返回任务状态，并通过所选承载方式提供等价的结果读取与取消能力；
6. 在失败、取消或结果未知时保留当前可确认事实，不得提交预期成功状态。

## 最小验证

| 编号 | 验证内容 | 通过条件 |
| --- | --- | --- |
| C01 | 接口说明 | 每项操作均有对象、控制、系统三段定义 |
| C02 | 输入校验 | 缺少任一维度或参数不符合类型、范围、枚举时拒绝执行 |
| C03 | 对象校验 | 目标容器存在、类型兼容、状态和容量满足条件 |
| C04 | 系统校验 | 设备状态、修订号和安全围栏在动作前通过 |
| C05 | 结果结构 | 响应同时包含对象变化、控制结果、系统状态与注意事项 |
| C06 | 异步语义 | 每次任务结果均返回三段事实，取消不提交预期成功状态 |
| C07 | 失败语义 | 失败诊断可定位到对象、控制或系统条件 |

## 声明示例

```json
{
  "implementation": "example-device-adapter",
  "fsp_version": "0.1",
  "interface_contract": {
    "dimensions": ["object", "control", "system"],
    "transport_agnostic": true,
    "asynchronous_result_supported": true
  }
}
```

此声明不要求公开接口 URL、命令名或供应商实现细节。
