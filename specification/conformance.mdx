## 符合性对象

| 角色 | 验证范围 |
| --- | --- |
| 编译/解释器 | FSP 定义解析、类型检查、中间程序和修订一致性 |
| 仿真器 | 参数、状态转换、系统围栏、完成条件和失败阻断 |
| 执行器 | 运行时检查、FSP 下发、任务处理、结果验证和状态提交 |
| FSP 服务 | 远程消息、分类请求、对象状态、系统任务、错误与安全行为 |
| 设备适配器 | FSP 与设备既有接口的映射及事实一致性 |

## 声明示例

```json
{
  "protocol": "ALL",
  "protocol_version": "2026-09-02",
  "transport": "https",
  "message_format": "json-rpc-2.0",
  "roles": ["compiler_interpreter", "simulator", "executor", "fsp_service"],
  "fsp": {
    "dimensions": ["operation", "object", "system"],
    "request_classes": ["read", "write", "invoke"],
    "system_tasks": true
  }
}
```

## FSP 最小要求

FSP 服务必须：

- 只通过远程 HTTPS 暴露基础端点；
- 实现 `fsp/read` 和 `fsp/invoke`；声明可写状态时实现 `fsp/write`；
- 为每项操作提供参数、对象和系统三个维度的完整定义；
- 将 `read`、`write` 和 `invoke` 作为风险分类并执行对应安全约束；
- 对 `write` 执行可写性、修订号和写后验证；
- 对 `invoke` 执行对象前置条件、系统围栏和结果验证；
- 对长任务实现 `fsp/get_task`，支持取消时实现 `fsp/cancel_task`；
- 使用统一结果、系统任务状态和诊断结构。

## 语言引擎最小要求

- 编译/解释器不得生成未在 FSP 设备定义中声明的操作或参数；
- 仿真器必须在隔离状态中运行，失败程序不得进入执行器；
- 执行器必须确认仿真通过和修订一致，并在执行前重新检查实际状态；
- 预期状态、仿真状态和实际设备状态必须明确区分；
- 只有经过运行时结果验证的状态变化可以提交。

## 最小验证集

| 编号 | 验证内容 | 通过条件 |
| --- | --- | --- |
| `C01` | 未声明操作 | 编译/解释器拒绝生成调用 |
| `C02` | 参数边界 | 类型、范围、枚举和单位错误均被拒绝 |
| `C03` | 修订冲突 | 不执行动作并返回诊断 |
| `C04` | 仿真失败 | 程序不进入执行器 |
| `C05` | 分类约束 | 读取不改状态，写入后回读，物理调用前后强制检查 |
| `C06` | 系统异步任务 | 状态按任务状态机变化，结果可查询 |
| `C07` | 结果未知 | 不把计划或仿真效果提交为实际状态 |
| `C08` | 适配器映射 | FSP 参数、底层调用、结果和状态变化一致 |
