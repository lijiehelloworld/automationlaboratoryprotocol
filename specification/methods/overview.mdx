## 定义

函数式实验方法把研究对象状态、参数、约束和可用设备能力组合成可计算程序：

```text
M: (Sₜ, θ, C, R) → (Sₜ₊₁, E, D)
```

方法必须由能力库中已经准入的函数组成，不能直接调用未声明设备能力。

## 输入

方法生成输入包括：

```text
用户实验需求
研究对象和当前状态
容器与样品状态
合格设备能力库
函数式能力签名
参数和状态约束
```

## 现有代码输出

`skill_all` 规定代码式方法必须：

- 定义 `generate_recipe()` 入口；
- 使用工作站命名空间调用物理能力；
- 从公共类型模块导入参数数据类；
- 循环中的设备调用显式展开；
- 在转换前完成优化和仿真。

```python
def generate_recipe():
    Liquid_Handling_Station_1ml_V2.open_caps(
        container_type="进样瓶",
        container_count=2,
        container_ids=[1, 2],
        open_cap_bottle_ids=[
            OpenCapBottle(bottle_id=1),
            OpenCapBottle(bottle_id=2),
        ],
        keep_cap=1,
    )

    Liquid_Handling_Station_1ml_V2.add_liquid_with_material(
        container_type="进样瓶",
        container_count=2,
        container_ids=[1],
        dispensing_plan=[
            DispensingPlan(
                sample_bottle_id=1,
                source_bottle=SourceBottle(
                    ingredient_name="试剂A",
                    source_volume_mL=0.5,
                    source_bottle_id=1,
                ),
            )
        ],
    )
```

函数、参数结构和状态约束来自现有函数式能力定义，不由方法生成器重新命名。

## 方法组合

函数式实验方法支持以下组合能力：

- 顺序执行；
- 显式展开的有限重复；
- 条件选择；
- 并行分支与汇合；
- 受保护资源区间。

现有模板中并行使用 `parallel_execution` 和 `branch`。循环必须显式展开，避免转换后产生无法解析的变量占位符。

## 转换输出

仿真通过后，现有转换器生成：

```text
实验名称
plan_name
实验流程
涉及工作站
path
steps
unknown_steps
```

`steps` 的字段固定为：

```text
step_number
id
workstation
operation
parameters
```

完整输出见[执行与证据闭环](/specification/methods/execution)。
