### 执行计划字段

| 字段 | 作用 |
| --- | --- |
| `实验名称`、`plan_name` | 提供面向人员与程序的计划名称 |
| `实验流程[]` | 提供可读的步骤摘要，不作为设备调用依据 |
| `涉及工作站[]` | 汇总计划绑定的工作站及操作 |
| `path` | 表达工作站之间的有向依赖关系 |
| `steps[]` | 保存可下发步骤的设备、操作和参数 |
| `steps[].step_number` | 确定步骤顺序 |
| `steps[].id` | 绑定 FSP `device_id` |
| `steps[].workstation` | 提供工作站显示名称 |
| `steps[].operation` | 保存已绑定的操作名称 |
| `steps[].parameters` | 保存通过校验的操作实参 |
| `unknown_steps` | 保存无法绑定的步骤；非空时禁止执行 |

## 下发方式

执行服务按 `steps` 顺序把每一步映射为 `fsp/invoke`：

```text
steps[].id         → device_id
steps[].operation  → 通过能力绑定解析为 command_id
steps[].parameters → 通过参数绑定解析为 arguments
```

设备操作是否同步或异步，由 FSP 操作定义和实际返回决定。

## 仿真输出

方法在进入物理执行前必须生成仿真报告：

```json
{
  "simulation_status": "passed",
  "verified_by": "run_simulation.py",
  "command_exit_code": 0,
  "operation_count": 6,
  "checks": [
    "调用仅使用已准入工作站函数",
    "开盖、加液、关盖和检测构成研究对象从 St 到 St+1 的状态演化",
    "强制条件失败时不提交研究对象的模拟状态"
  ]
}
```

仿真通过只证明方案在当前函数和状态模型中可运行，不证明物理设备已经执行。

## 状态提交

```text
仿真或执行成功且完成条件满足
  → 保存结果和诊断
  → 提交实际状态变化

强制校验失败、仿真阻断或设备结果未知
  → 不提交预期成功状态
  → 保留原状态或重新读取实际状态
  → 返回诊断并重新生成或修订方法
```

## 失败回退与再验证

执行服务不能把计划中的预期状态当作真实结果。每步完成后先读取或接收设备确认的对象、控制结果和系统状态，再决定是否提交研究对象状态。

1. 设备成功且返回值满足操作完成条件：保存结果、诊断和证据引用，提交实际状态变化；
2. 设备失败、取消或返回未知结果：不提交预期状态，保留已确认状态并读取对象和系统最新值；
3. 将失败步骤、实际状态、能力修订号和诊断反馈给方法生成与验证阶段；
4. 只有重新生成的方法通过完整验证并重新绑定后，才允许形成新的执行任务。

这使“生成—验证—执行”形成可追溯闭环：重新执行前必须以设备实际状态为新的输入，而不是沿用失败前的状态假设。

## 真实执行证据边界

真实执行至少应当返回：

- 实际调用的操作和参数；
- 开始和完成状态；
- 实际对象和系统状态；
- 结果或诊断；
- 可以关联到研究对象来源记录的执行引用。

### 执行证据输出示例

```json
{
  "execution_id": "exec-a01-001",
  "plan_name": "A01 CoFeNi 高熵氧化物：样品准备与 UV-Vis 表征最小闭环",
  "status": "succeeded",
  "started_at": "2026-09-01T12:00:00Z",
  "completed_at": "2026-09-01T12:08:00Z",
  "step_results": [
    {
      "step_number": 1,
      "device_id": "2002186824385539",
      "command_id": "open_caps",
      "status": "succeeded",
      "task_id": null,
      "result": {"opened_bottles": [1, 2], "opened_bottles_count": 2},
      "diagnostics": []
    }
  ],
  "state_committed": true,
  "evidence_refs": ["evidence://exec-a01-001/step-1"]
}
```

| 输出字段 | 作用 |
| --- | --- |
| `execution_id` | 唯一标识一次计划执行 |
| `status` | 汇总执行是否成功、失败、取消或结果未知 |
| `started_at`、`completed_at` | 记录真实运行时间边界 |
| `step_results[]` | 保存每步实际设备、指令、任务、结果和诊断 |
| `state_committed` | 表示是否已经依据设备确认结果提交研究对象状态 |
| `evidence_refs[]` | 把执行结果关联到可审计证据位置 |

执行服务必须使用[异步任务](/specification/fsp/async-tasks)定义的任务状态和本页定义的证据记录，不得以执行计划中的预期状态代替设备确认结果。
