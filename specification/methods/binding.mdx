description: "把验证后的函数调用绑定到现有工作站、操作和参数"
---

## 模块作用

能力匹配读取合格设备能力库，根据方法需要的函数、容器状态、参数范围和设备可用性选择工作站。当前 `skill_all` 没有独立的候选设备评分 JSON，因此本规范不编造 `match_score` 或候选列表。

## 输入

```text
已通过仿真的代码式方法
函数式能力签名
工作站编码和名称
工作站操作及参数约束
当前设备可用状态
```

## 匹配依据

每个方法调用必须能够在合格能力库中找到：

```text
工作站 namespace
函数名称
参数名称和类型
初始状态
状态更新
返回值
异常和约束
```

## 绑定输出

现有转换器把绑定结果写入最终 JSON：

```json
{
  "step_number": 1,
  "id": "2002186824385539",
  "workstation": "移液平台_1ml_V2",
  "operation": "开盖",
  "parameters": {
    "container_type": "进样瓶",
    "container_count": 2,
    "container_ids": [1, 2]
  }
}
```

加液步骤保持现有参数结构：

```json
{
  "step_number": 2,
  "id": "2002186824385539",
  "workstation": "移液平台_1ml_V2",
  "operation": "加液_物料绑定",
  "parameters": {
    "container_type": "进样瓶",
    "container_count": 2,
    "container_ids": [1],
    "dispensing_plan": [
      {
        "原液瓶编号": 1,
        "加液体积": 0.5
      }
    ]
  }
}
```

## 路径输出

设备间关系使用现有 `path` 字段：

```json
{
  "开始节点id": ["移液平台_1ml_V20节点id"],
  "移液平台_1ml_V20节点id": ["紫外可见光谱仪_V10节点id"],
  "紫外可见光谱仪_V10节点id": ["结束节点id"]
}
```

## 无法绑定

无法识别或无法绑定的步骤使用现有 `unknown_steps` 字段。没有真实产物支持时，不增加另一套 `no_compatible_device` 或候选评分返回格式。
