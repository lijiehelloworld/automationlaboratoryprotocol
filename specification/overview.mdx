## 目标

ALL 把实验目标转换为结构化、可计算、可仿真并可由物理设备执行的程序，同时保留对象状态、实际结果和诊断。

## 组成

| 模块 | 主要职责 |
| --- | --- |
| 编译/解释器 | 读取实验意图与 FSP 设备定义，生成类型化函数和中间程序 |
| 仿真器 | 在不调用设备的条件下验证参数、对象状态、系统围栏和完成条件 |
| 执行器 | 将通过仿真的程序转换为 FSP 请求，处理同步或异步结果 |
| FSP | 从操作、对象和系统三个维度统一设备通信 |

## 角色

| 角色 | 职责 |
| --- | --- |
| 调用方 | 提出目标、提供上下文并接收结果 |
| ALL 语言引擎 | 编译、解释、仿真和执行实验程序 |
| FSP 服务 | 向已配置设备下发分类请求并返回状态、结果和诊断 |
| 设备适配器 | 将 FSP 语义映射到设备已有接口 |
| 物理设备 | 被动执行操作并产生可确认事实 |

协议客户端能力集成在用户应用、自动化系统或智能体运行时中，不作为独立服务。

## 主交互

```text
实验目标与对象状态
  → 编译/解释
  → 仿真验证
  → 执行器运行时检查
  → FSP 分类请求
  → 设备执行
  → 实际结果与诊断
```

## 非目标

ALL 不规定设备固件、驱动、实验室调度算法、模型类型或厂商 API 形式，也不要求设备重写已有接口。
