---
title: "协议概述"
description: "说明 ALL 负责什么、FSP 负责什么，以及两者如何配合。"
---

ALL 把实验目标转换为可编译、可仿真并可执行的程序。ALL 语言引擎负责生成和验证程序；FSP 约束语言引擎与已配置设备之间的接口语义。

| 模块 | 职责 |
| --- | --- |
| 编译/解释器 | 把实验意图、容器状态和 FSP 设备定义转换为类型化中间程序 |
| 仿真器 | 在隔离状态中验证参数、状态变化、系统围栏和完成条件 |
| 执行器 | 通过符合 FSP 的设备接口执行已通过仿真的程序，并核验实际结果 |
| FSP | 用对象、操作和系统三段结构约束设备接口说明、输入和输出 |

## 主交互

```text
实验目标与容器状态
  → 编译/解释
  → 仿真验证
  → 执行器运行时检查
  → 符合 FSP 的设备接口
  → 设备实际结果、状态与注意事项
```

设备可以保留原有 API、SDK 或驱动；适配层负责映射，设备不负责解释实验目标。
