## 概述

Automation Laboratory Language（ALL，自动化实验室语言）是一种让 Agent、自动化系统和用户应用以统一方式发现并调用实验室设备的远程通信规范。

ALL 只定义四个协议模块：

| 模块 | 职责 |
| --- | --- |
| 系统 `system/*` | 鉴权后的发现、能力清单、设备状态和事件 |
| 对象 `objects/*` | 研究对象类型、实例、样品、容器、证据和来源 |
| 操作 `operations/*` | 读取、写入、调用、长任务和取消 |
| Workflow `workflows/*` | 固定模板的查询、校验和运行 |

服务端不得在标准能力清单中声明其他顶层方法命名空间。

## 核心目标

ALL 使客户端能够：

- 通过 OAuth 2.1 远程授权访问设备；
- 发现协议版本、设备和四模块能力；
- 获取机器可读的数据结构、权限和安全要求；
- 查询并维护研究对象的协议事实；
- 执行经过声明和校验的读取、写入与调用；
- 查询长任务、补充输入并请求安全取消；
- 查询、校验和运行设备发布的 Workflow；
- 使用修订号、结构化错误和事件协调状态。

## 协议角色

| 角色 | 责任 |
| --- | --- |
| 客户端 | 集成在 Agent、自动化系统或用户应用中；获取令牌、发现能力并发送请求 |
| 服务端 | 提供 ALL HTTPS 端点，验证权限并公开四模块能力 |
| 设备 | 由 `device_id` 唯一寻址的能力、状态和执行边界 |
| 授权服务器 | 验证主体并签发适用于 ALL 资源的访问令牌 |

客户端不是独立服务要求；它是调用方内部的协议能力。服务端内部实现不属于线协议角色。

## 远程和无会话

ALL 使用 HTTPS 和 JSON-RPC 2.0。每个请求都携带协议版本、客户端信息、请求标识、方法路由头和访问令牌。

ALL 不建立协议会话，不依赖连接粘性。跨请求状态必须使用显式对象标识、操作任务标识、订阅标识、校验句柄或补充输入句柄。

## 研究对象原则

对象模块只使用 `ResearchObject`（研究对象）。设备直接读取、写入、处理、检查、测量或测试的实体都通过研究对象类型和实例表达；规范结构固定为身份、样品、容器、证据、来源与可扩展字段。

对象本身只记录已确认事实。需要改变物理状态的行为必须通过操作执行，不能用对象更新接口伪造。

## 操作原则

操作定义必须明确：

- 名称和种类；
- 输入与输出数据结构；
- 研究对象角色与工作站绑定；
- 所需 OAuth 权限；
- 前置条件、注意事项、强制/建议约束和声明状态变化；
- 是否改变物理状态；
- 是否支持试运行、幂等、长任务、补充输入和取消；
- 默认超时。

客户端只能调用能力清单声明的操作。

## Workflow 原则

Workflow 只提供查询、读取、校验和运行四个接口。每个模板以 `name + version + digest` 固定，只能组合已声明操作，并支持顺序、有限循环、条件分支、并行汇合和受保护区间五类组合算子。

## 规范性用语

- **必须**：符合本版本的强制要求。
- **不得**：明确禁止的行为。
- **应当**：通常应采用，只有明确理由时可以偏离。
- **不应**：通常不采用，只有明确理由时可以偏离。
- **可以**：由设备能力或部署策略决定。

## 适用范围

ALL 适用于能够通过受控远程服务公开能力的实验室设备、传感器、相机、机器人、执行机构、自动化工作站和组合设备。

ALL 不提供硬实时控制。运动闭环、温控闭环、急停、限位、安全门和毫秒级联锁必须由设备固件、控制器或等效本地安全层执行。
