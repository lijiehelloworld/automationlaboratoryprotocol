## 设备发现

### 输入

```json
{
  "jsonrpc": "2.0",
  "id": "discover-1",
  "method": "fsp/discover",
  "params": {}
}
```

### 输出

```json
{
  "jsonrpc": "2.0",
  "id": "discover-1",
  "result": {
    "result_type": "complete",
    "value": {
      "devices": [
        {
          "device_id": "2002186824385539",
          "name": "Liquid_Handling_Station_1ml_V2",
          "capability_revision": "12",
          "available": true
        }
      ]
    },
    "diagnostics": []
  }
}
```

设备名称用于显示；稳定引用必须使用 `device_id`。

### 发现输出字段

| 字段 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `devices` | `array[object]` | 是 | 当前 FSP 服务声明的设备列表 |
| `devices[].device_id` | `string` | 是 | 稳定设备标识 |
| `devices[].name` | `string` | 是 | 设备名称 |
| `devices[].capability_revision` | `string` | 是 | 当前能力数据修订号 |
| `devices[].available` | `boolean` | 是 | 设备当前是否可接收后续请求 |

## 能力数据集

FSP 服务必须实现 `fsp/discover` 和 `fsp/get_capabilities`。它们是 FSP 层的统一能力获取接口：负责发现设备、分配或维护 `device_id`、聚合设备能力的对象、控制和系统信息，并向调用方返回结构化能力数据集。

单个设备不要求原生实现这两个方法；设备侧只需提供或可映射相应事实信息。`fsp/get_capabilities` 使用结构化 JSON 返回能力数据集。

接口按清单方式组织：每个操作都以独立条目提供稳定标识、名称、说明、输入约束、输出约束和执行特征。调用方只能调用本次结果中列出的操作，不能根据名称猜测未声明操作。

```text
FSPCapabilityDataset
├── device
├── revision
├── objects[]
├── operations[]
└── system
```

### 请求

```json
{
  "jsonrpc": "2.0",
  "id": "capability-1",
  "method": "fsp/get_capabilities",
  "params": {
    "device_id": "lab.device-01",
    "if_revision": "rev-20260902-01"
  }
}
```

| 参数 | 类型 | 是否必需 | 范围与约束 | 作用 |
| --- | --- | --- | --- | --- |
| `device_id` | `string` | 是 | 长度 `1..128`；必须来自当前 FSP 服务的 `fsp/discover` 结果 | 指定要读取能力的设备 |
| `if_revision` | `string` | 否 | 长度 `1..128`；值为调用方已经完整缓存的能力修订号 | 用于条件读取；与当前修订号相同则返回 `not_modified` |

`params` 不得携带未声明字段。`if_revision` 不匹配不是错误，服务端必须返回当前完整能力数据集；设备不存在、参数类型错误或空字符串必须返回协议错误。

### 成功结果字段

| 字段 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `device` | `object` | 是 | 设备标识、名称和总体说明 |
| `device.device_id` | `string` | 是 | 长度 `1..128`；稳定设备标识 |
| `device.name` | `string` | 是 | 长度 `1..128`；设备名称 |
| `device.description` | `string` | 是 | 长度 `0..4096`；能力总体说明 |
| `revision` | `string` | 是 | 长度 `1..128`；本次能力数据修订号 |
| `ttl_ms` | `integer` | 是 | `0..86400000`；`0` 表示本结果不可缓存，其他值表示最大缓存时长（毫秒） |
| `cache_scope` | `string` | 是 | `none` 或 `service`；表示结果是否可在当前 FSP 服务范围内缓存 |
| `objects` | `array[object]` | 是 | FSP 对象类型定义；为空时返回 `[]` |
| `operations` | `array[object]` | 是 | 已声明的可调用操作；为空时返回 `[]` |
| `system` | `object` | 是 | 总体能力、运行状态字段和安全围栏定义 |
| `diagnostics` | `array[object]` | 是 | 非阻断提示或结果诊断；没有内容时返回 `[]` |

空数组表示当前设备没有该类对象或指令，不能省略字段。

### 操作条目

每个 `operations[]` 条目相当于一项可调用能力的完整清单。`command_id` 在同一设备能力数据集内必须唯一；调用方只能使用该字段调用操作。

| 字段 | 类型 | 是否必需 | 范围与约束 |
| --- | --- | --- | --- |
| `command_id` | `string` | 是 | 长度 `1..128`；仅允许 ASCII 字母、数字、`_`、`-`、`.`；同一数据集内唯一 |
| `name` | `string` | 是 | 长度 `1..128`；面向人的操作名称 |
| `description` | `string` | 是 | 长度 `1..4096`；说明操作目的、作用对象和可观察结果 |
| `command_class` | `string` | 是 | `read`、`write` 或 `invoke` |
| `execution_mode` | `string` | 是 | `sync` 或 `async` |
| `parameters` | `array[object]` | 是 | 参数的展开定义；每项必须有名称、类型、必填性、说明和适用约束 |
| `input_schema` | `object` | 是 | 参数对象定义；必须列出参数类型、必填项、范围、单位、枚举和嵌套字段 |
| `constraints` | `array[string]` | 是 | 影响调用是否允许的前置状态或跨字段约束；无约束时返回 `[]` |
| `effects` | `object` | 是 | 成功完成后可能产生的对象或系统状态变化；只描述可提交的实际变化 |
| `returns` | `array[object]` | 是 | 返回字段的展开定义；每项必须有名称、类型和适用约束 |
| `output_schema` | `object` | 是 | 成功结果定义；异步操作必须包含任务标识和任务状态 |

`parameters` 必须与 `input_schema` 表达同一组参数，`returns` 必须与 `output_schema` 表达同一组输出。`input_schema` 与 `output_schema` 必须是有效的 JSON Schema 2020-12 对象，使用 `type`、`properties`、`required`、`enum`、`minimum`、`maximum`、`exclusiveMinimum`、`minLength`、`maxLength`、`items` 和 `additionalProperties` 等核心字段。跨字段、状态或物理容量约束无法只用 Schema 表达时，必须同时写入 `constraints[]`。

### 对象与系统条目

| 分区 | 必需字段 | 约束 |
| --- | --- | --- |
| `objects[]` | `object_type_id`、`variant_id`、`name`、`properties`、`states` | 类型标识长度 `1..128`；同一数据集内唯一；物理值未知时使用 `null`，不得推测 |
| `system.availability_states` | `array[string]` | 至少包含一个可用状态和一个不可用状态 |
| `system.status_fields` | `array[string]` | 声明后才能由 `fsp/read` 返回 |
| `system.safety_fences` | `array[object]` | 每项必须有名称和可执行的约束说明；没有围栏时返回 `[]` |

## 条件读取

调用方可以携带 `if_revision`。仅当该值等于当前能力修订号时，服务端才返回未修改结果；该结果不包含 `objects`、`operations` 或 `system`，调用方必须继续使用已完整缓存的数据集。

```json
{
  "jsonrpc": "2.0",
  "id": "capability-1",
  "result": {
    "result_type": "not_modified",
    "value": {
      "revision": "rev-20260902-02",
      "ttl_ms": 300000,
      "cache_scope": "service"
    },
    "diagnostics": []
  }
}
```

调用方未缓存完整能力数据集时不得发送 `if_revision`；服务端不得把未修改结果用于替代首次完整读取。

## 错误输出

设备不存在、参数错误或版本不支持时，请求不得返回部分能力数据：

```json
{
  "jsonrpc": "2.0",
  "id": "capability-1",
  "error": {
    "code": -32004,
    "message": "设备不存在",
    "data": {
      "diagnostics": [
        {
          "code": "device_not_found",
          "path": "params.device_id",
          "message": "无法读取目标设备能力"
        }
      ]
    }
  }
}
```

错误响应不得包含其他设备的能力、状态或内部实现信息。

| 诊断代码 | 触发条件 | `path` | 服务端行为 |
| --- | --- | --- | --- |
| `invalid_request` | 缺少 `device_id`、类型错误、空字符串或存在未知参数 | 对应请求字段 | 返回协议错误，不返回能力数据 |
| `device_not_found` | `device_id` 不在当前 FSP 服务的设备目录中 | `params.device_id` | 返回协议错误，不返回能力数据 |
| `invalid_revision` | `if_revision` 不是合法字符串 | `params.if_revision` | 返回协议错误，不返回能力数据 |
| `capability_unavailable` | 服务暂时无法生成一致的能力数据集 | `params.device_id` | 返回协议错误，不返回部分对象或操作 |

以下变化必须产生新的能力修订号：

- 新增、删除或修改对象类型；
- 新增、删除或修改操作签名、约束或返回值；
- 修改系统能力说明或安全围栏；
- 修改会影响调用方行为的适配映射。

设备当前忙闲状态和任务进度不改变能力修订号。

## 能力数据的事实地位

FSP 能力数据是设备能力的事实来源。由其生成的设备技能描述、函数式技能或其他模型可读说明不得改变对象属性、操作参数、强制约束和系统安全围栏。
