## 设备发现

### 输入

```json
{
  "jsonrpc": "2.0",
  "id": "discover-1",
  "method": "fsp/discover",
  "params": {}
}
```

### 输出

```json
{
  "jsonrpc": "2.0",
  "id": "discover-1",
  "result": {
    "result_type": "complete",
    "value": {
      "devices": [
        {
          "device_id": "2002186824385539",
          "name": "Liquid_Handling_Station_1ml_V2",
          "capability_revision": "12",
          "available": true
        }
      ]
    },
    "diagnostics": []
  }
}
```

设备名称用于显示；稳定引用必须使用 `device_id`。

### 发现输出字段

| 字段 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `devices` | `array[object]` | 是 | 当前 FSP 服务声明的设备列表 |
| `devices[].device_id` | `string` | 是 | 稳定设备标识 |
| `devices[].name` | `string` | 是 | 设备名称 |
| `devices[].capability_revision` | `string` | 是 | 当前能力数据修订号 |
| `devices[].available` | `boolean` | 是 | 设备当前是否可接收后续请求 |

## 能力数据集

FSP 服务必须实现 `fsp/discover` 和 `fsp/get_capabilities`。它们是 FSP 层的统一能力获取接口：负责发现设备、分配或维护 `device_id`、聚合设备能力的对象、控制和系统信息，并向调用方返回结构化能力数据集。

单个设备不要求原生实现这两个方法；设备侧只需提供或可映射相应事实信息。`fsp/get_capabilities` 使用结构化 JSON 返回能力数据集。

```text
FSPCapabilityDataset
├── device
├── revision
├── objects[]
├── operations[]
└── system
```

### 输入

```json
{
  "jsonrpc": "2.0",
  "id": "capability-1",
  "method": "fsp/get_capabilities",
  "params": {
    "device_id": "2002186824385539"
  }
}
```

| 参数 | 类型 | 是否必需 | 约束 |
| --- | --- | --- | --- |
| `device_id` | `string` | 是 | 必须来自当前 FSP 服务的 `fsp/discover` 结果 |
| `if_revision` | `string` | 否 | 调用方已缓存的能力修订号 |

### 成功输出字段

| 字段 | 类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| `device` | `object` | 是 | 设备标识、名称和总体说明 |
| `device.device_id` | `string` | 是 | 稳定设备标识 |
| `device.name` | `string` | 是 | 设备名称 |
| `device.description` | `string` | 是 | 能力总体说明 |
| `revision` | `string` | 是 | 本次能力数据修订号 |
| `objects` | `array[object]` | 是 | FSP 对象类型定义 |
| `operations` | `array[object]` | 是 | 设备具体指令定义；每项含 `command_id` 和 `command_class` |
| `system` | `object` | 是 | 总体能力、运行状态字段和安全围栏定义 |

空数组表示当前设备没有该类对象或指令，不能省略字段。

## 条件读取

调用方可以携带 `if_revision`。未变化时服务端返回：

```json
{
  "result_type": "not_modified",
  "revision": "12",
  "diagnostics": []
}
```

## 错误输出

设备不存在、参数错误或版本不支持时，请求不得返回部分能力数据：

```json
{
  "jsonrpc": "2.0",
  "id": "capability-1",
  "error": {
    "code": -32004,
    "message": "设备不存在",
    "data": {
      "diagnostics": [
        {
          "code": "device_not_found",
          "path": "params.device_id",
          "message": "无法读取目标设备能力"
        }
      ]
    }
  }
}
```

错误响应不得包含其他设备的能力、状态或内部实现信息。

以下变化必须产生新的能力修订号：

- 新增、删除或修改对象类型；
- 新增、删除或修改操作签名、约束或返回值；
- 修改系统能力说明或安全围栏；
- 修改会影响调用方行为的适配映射。

设备当前忙闲状态和任务进度不改变能力修订号。

## 能力数据的事实地位

FSP 能力数据是设备能力的事实来源。由其生成的设备技能描述、函数式技能或其他模型可读说明不得改变对象属性、操作参数、强制约束和系统安全围栏。
