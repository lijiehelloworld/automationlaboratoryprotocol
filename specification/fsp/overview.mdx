---
title: "FSP 概述"
description: "ALL 内部面向设备通信的函数状态协议"
---

Function State Protocol（FSP，函数状态协议）把不同设备的能力统一表达为对象、操作和系统三个分区，并提供发现、读取、调用、异步任务和诊断语义。

## 三类能力

| 分区 | 回答的问题 |
| --- | --- |
| 对象 | 设备能够识别或处理什么对象，对象现在是什么状态 |
| 操作 | 设备能够执行什么函数，参数、约束、状态变化和返回值是什么 |
| 系统 | 设备整体能做什么、当前状态如何、有哪些安全围栏 |

FSP 不增加第四类设备能力。函数式实验方法属于 ALL 的方法层，不由工作站作为独立模块发布。

## 标准交互

```text
fsp/discover
  → fsp/get_capabilities
  → fsp/read
  → fsp/write（声明可写状态时）
  → fsp/invoke
  → fsp/get_task（异步时）
  → 状态与诊断返回
```

## 底层接口无关

FSP 描述统一语义，不要求设备采用相同底层技术：

```text
调用方
  → FSP 服务或适配器
      → 现有 HTTP API
      → 厂商 SDK
      → RPC 或消息接口
      → 本地驱动或设备协议
```

适配方式属于[设备接入与接口适配](/specification/device-integration/overview)。设备只要能够通过服务或适配器提供对象、操作和系统说明，即可进入能力准入流程。

## 方法摘要

| 方法 | 所需权限 | 作用 |
| --- | --- | --- |
| `fsp/discover` | `fsp.read` | 发现可见设备 |
| `fsp/get_capabilities` | `fsp.read` | 获取对象、操作和系统定义 |
| `fsp/read` | `fsp.read` | 读取对象或系统当前状态 |
| `fsp/write` | `fsp.execute` | 写入设备已声明为可写的目标状态 |
| `fsp/invoke` | `fsp.execute` | 调用已声明操作 |
| `fsp/get_task` | `fsp.read` | 读取异步任务进度和结果 |
| `fsp/cancel_task` | `fsp.execute` | 请求取消可取消任务 |
| `fsp/subscribe` | `fsp.read` | 订阅状态或任务事件 |

## 设备要求

工作站不需要原生实现 FSP，也不要求重新设计已有接口。符合性要求只检查 FSP 服务可观察到的数据和行为，不检查设备内部代码组织。

## 指令类别与具体指令

读取、写入和调用只是 `command_class` 的三个允许值。实际设备能力由多条具体指令组成：

```text
operations[]
├── command_id: 稳定指令标识
├── command_class: read | write | invoke
├── parameters: 参数与约束
├── effects: 状态变化
└── returns: 返回值与诊断
```

调用方必须先从能力数据取得 `command_id`，不能把 `read`、`write` 或 `invoke` 当成设备唯一的三条动作。
