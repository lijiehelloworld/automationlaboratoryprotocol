---
title: "系统"
description: "设备状态、安全围栏、异步任务和注意事项"
---

系统维度说明设备此刻是否允许执行操作，以及执行后设备处于什么状态。它包含设备状态、安全围栏、执行模式、异步任务和注意事项。

## 请求中的系统条件

```json
{
  "system": {
    "expected_device_state": "idle",
    "expected_system_revision": "system-21",
    "execution_mode": "async",
    "preconditions": [
      "设备无故障",
      "目标容器已定位",
      "当前不存在冲突任务"
    ],
    "safety_fences": [
      "单次加液量不得超过操作上限",
      "目标容器剩余容量必须大于等于加液量"
    ]
  }
}
```

## 响应中的系统事实

```json
{
  "system": {
    "device_state": "busy",
    "system_revision": "system-22",
    "safety_checks": [
      {"rule": "设备无故障", "passed": true},
      {"rule": "容器剩余容量足够", "passed": true}
    ],
    "task": {
      "task_id": "task-001",
      "status": "queued",
      "cancellable": true
    },
    "notices": ["任务执行期间不得移动目标容器"],
    "observed_at": "2026-09-02T06:00:00Z"
  }
}
```

## 异步任务

当 `execution_mode=async` 时，设备接口或适配层必须返回 `system.task`。实现可以通过 HTTP、CLI、MCP、RPC 或 SDK 提供等价的任务查询与取消能力，但 FSP 不规定其名称或路径。

任务状态仅可为 `queued`、`running`、`succeeded`、`failed`、`cancelled` 或 `unknown`。每次任务状态查询都必须返回对象、控制和系统三段事实：对象给出当前容器状态，控制给出执行进度或结果，系统给出任务状态、安全检查和注意事项。

只有任务进入 `succeeded` 且结果验证通过后，设备或执行器才可提交对象新状态。`failed`、`cancelled` 和 `unknown` 均不得提交预期成功状态。
