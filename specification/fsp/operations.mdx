## 定义

操作是设备通过 FSP 暴露的可调用能力。FSP 关注操作语义，不强制设备采用特定 URL、HTTP 方法或驱动实现。

每个操作至少说明：稳定指令标识、指令类别、名称、能力说明、初始状态、状态更新、参数、约束、返回值、诊断和同步或异步模式。

`command_class` 只能是：

| 值 | 含义 |
| --- | --- |
| `read` | 读取设备或对象状态，不改变物理状态 |
| `write` | 把声明为可写的状态设置为目标值，可能触发设备动作 |
| `invoke` | 执行设备暴露的函数 |

## 非规范性完整操作集

以下三个操作共同构成一个容器开盖、加液、关盖的设备技能示例。具体设备实现可以声明不同操作，但每条操作必须提供同等完整的信息。

### 开盖 `open_caps`

| 项目 | 定义 |
| --- | --- |
| `command_class` | `invoke` |
| `execution_mode` | `sync` |
| 前置状态 | `container_status == "有盖"`；样品可为空、液体、固体或固液混合物 |
| 状态变化 | `container_status: 有盖 → 无盖`；样品状态保持不变 |

| 参数 | 类型 | 必填 | 范围或枚举 | 作用 |
| --- | --- | --- | --- | --- |
| `container_type` | `enum` | 是 | `进样瓶`、`50ml耐热瓶` | 指定容器类型 |
| `container_count` | `int` | 是 | `1..10` | 指定当前实验中的容器总数 |
| `container_ids` | `array[int]` | 是 | `max(container_ids) <= container_count` | 指定本次涉及的容器 |
| `open_cap_bottle_ids` | `array[object]` | 是 | 每个 `bottle_id` 必须属于 `container_ids` | 指定实际开盖瓶号 |
| `keep_cap` | `int` | 是 | `0` 或 `1`，默认 `1` | 指定是否保留瓶盖供后续关盖 |

强制约束：容器必须有盖；容器数量与编号必须匹配；开盖瓶号必须属于本次容器；`keep_cap` 只能为 `0` 或 `1`。成功返回 `container_type`、`container_status`、`sample_status`、`opened_bottles[]` 和 `opened_bottles_count`。

### 关盖 `close_caps`

| 项目 | 定义 |
| --- | --- |
| `command_class` | `invoke` |
| `execution_mode` | `sync` |
| 前置状态 | `container_status == "无盖"`，且已经完成对应开盖操作 |
| 状态变化 | `container_status: 无盖 → 有盖`；样品状态保持不变 |

| 参数 | 类型 | 必填 | 范围或枚举 | 作用 |
| --- | --- | --- | --- | --- |
| `container_type` | `enum` | 是 | `进样瓶`、`50ml耐热瓶` | 指定容器类型 |
| `container_count` | `int` | 是 | `1..10` | 指定当前实验中的容器总数 |
| `container_ids` | `array[int]` | 是 | `max(container_ids) <= container_count` | 指定本次涉及的容器 |
| `close_cap_bottle_ids` | `array[object]` | 是 | 每个 `bottle_id` 必须属于 `container_ids` | 指定实际关盖瓶号 |

强制约束：容器必须无盖；容器数量与编号必须匹配；关盖瓶号必须属于本次容器；容器内液体体积不得超过 30 mL。成功返回 `container_type`、`container_status`、`sample_status`、`closed_bottles[]` 和 `closed_bottles_count`。

  "initial_state": {
    "container_type": ["进样瓶", "50ml耐热瓶"],

  "effects": {
    "container_status": "无盖",
    "sample_status": {

  "parameters": [

上述示例完整展示操作、参数层级、范围、约束和返回字段。`execution_mode` 取值只能是 `sync` 或 `async`，必须由 FSP 适配器根据设备接口声明，不能由转换器猜测。

## 参数要求

参数定义应当包含下列适用字段：

```text
name
type
unit
required
default
minimum / maximum
allowed_values
description
children
constraints
```

嵌套参数必须展开到可验证层级。例如 `dispensing_plan` 应当说明 `sample_bottle_id`、`source_bottle_id`、`ingredient_name` 和 `source_volume_mL`，不能只写“对象数组”。

## 调用

```json
{
  "jsonrpc": "2.0",
  "id": "invoke-1",
  "method": "fsp/invoke",
  "params": {
    "device_id": "2002186824385539",
    "command_id": "add_liquid_with_material",
    "arguments": {
      "container_type": "进样瓶",
      "container_count": 2,
      "container_ids": [1],
      "dispensing_plan": [
        {
          "sample_bottle_id": 1,
          "source_bottle": {
            "ingredient_name": "试剂A",
            "source_volume_mL": 0.5,
            "source_bottle_id": 1
          }
        }
      ]
    },
    "expected_revision": "7"
  }
}
```

最终执行计划中的 `operation` 和参数由能力绑定模块解析为这里的 `command_id` 与函数参数，不能直接按字符串猜测。

## 写入

只有能力数据将某个字段声明为可写时，调用方才能使用 `fsp/write`。请求参数与 `fsp/invoke` 使用相同外层：`device_id`、能力中取得的 `command_id`、`arguments` 和 `expected_revision`。

本页非规范性设备示例只声明函数式调用，因此不提供该设备的写入指令示例。其他设备只有在能力数据声明可写字段后才能发布相应写入指令。

## 强制约束

操作开始前必须校验能力说明中的强制条件，包括：

- 初始容器状态；
- 样品状态；
- 参数类型、范围和枚举；
- 容器数量与编号关系；
- 多参数耦合约束；
- 系统安全围栏。

所有强制错误必须在 `diagnostics` 中返回。存在强制错误时不得接触物理设备，也不得提交研究对象新状态。

## 返回

同步成功时，返回值必须符合操作定义中的 `returns`，并包含实际状态变化。异步操作返回任务句柄，见[异步任务](/specification/fsp/async-tasks)。

### 同步输出示例

```json
{
  "result_type": "complete",
  "value": {
    "status": "succeeded",
    "state_committed": true,
    "result": {
      "container_type": "进样瓶",
      "container_status": "无盖",
      "sample_status": "空",
      "opened_bottles": [1, 2],
      "opened_bottles_count": 2
    },
    "revision": "8"
  },
  "diagnostics": []
}
```

| 输出字段 | 作用 |
| --- | --- |
| `status` | 表示操作成功、失败或结果未知 |
| `state_committed` | 表示是否已依据设备确认结果提交状态 |
| `result` | 保存操作定义中声明的返回字段 |
| `revision` | 返回操作完成后的新状态修订号 |
| `diagnostics[]` | 保存稳定编码、消息、字段路径和重试信息 |
